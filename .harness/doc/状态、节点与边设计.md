# One and Only 项目 · LangGraph 架构总结（最新版）

## 1. 核心思路
- 去掉人格参数、去掉 Embedding 风格向量，改用 **LoRA 微调模型** 控制语言风格。
- 情绪用 **Valence/Arousal/Control（VAC三维）** 表示。
- Live2D 动作：**VAC → 自训练小模型 → 动作参数**。
- 流程改为：**MemoryRetrieve → PlanExecute → Evaluate → FinalOutput**（规划与执行合并）。
- 支持后续扩展 **Skills/工具调用**，不改动主链路。

---

## 2. 共享状态（GlobalState）
```python
GlobalState:
  # 对话核心
  messages: Annotated[list[BaseMessage], add_messages]  # 对话历史
  user_input: str                                       # 用户当前输入
  response_text: str                                    # 模型回复文本

  # 认知处理
  plan: str                                             # 执行计划（预留字段）
  memory: Optional[str]                                 # 召回长期记忆内容

  # 情绪
  emotion_vac: dict[str, float]                         # 情绪VAC：Valence/Arousal/Control
                                                        # {'valence': 0.8, 'arousal': 0.3, 'control': 0.5}

  # 评估相关
  need_evaluate: bool                                   # 是否需要评估
  retry_times: int                                      # 重试次数
  error_message: Optional[str]                          # 错误信息
```

---

## 3. 节点设计（共4个）

### 3.1 MemoryRetrieve（记忆检索节点）
- **功能**：从外挂知识库中检索相关对话需要的信息
- **输入**：`user_input`, `messages`
- **输出**：`memory`
- **实现**：使用memory_manager agent，通过工具检索相关记忆

### 3.2 PlanExecute（规划与执行合并节点）
- **功能**：理解意图、生成回复、决策是否需要评估
- **输入**：`user_input`, `messages`, `memory`
- **输出**：`response_text`, `need_evaluate`
- **实现**：使用plan_execute agent，集成规划和执行功能
- **特点**：将原Plan和Execute节点合并，简化流程

### 3.3 Evaluate（评估节点）
- **功能**：评估执行结果是否合理，决定是否需要重试
- **输入**：`plan`, `response_text`, `memory`, `user_input`, `retry_times`
- **输出**：`need_evaluate`, `error_message`, `retry_times`
- **实现**：使用evaluator LLM，评估回复质量和一致性

### 3.4 FinalOutput（最终输出节点）
- **功能**：生成最终输出，包括文本、情绪参数，异步更新记忆
- **输入**：`response_text`, `user_input`, `retry_times`, `messages`
- **输出**：`response_text`, `emotion_vac`, `messages`
- **实现**：
  - 使用summarizer LLM调整文本风格和生成情绪参数
  - 异步更新外挂记忆库（后台线程）
  - 根据重试次数选择正常或错误响应模板

## 4. 边与流程

### 4.1 流程图
```
Start
  ↓
MemoryRetrieve（检索相关记忆）
  ↓
PlanExecute（理解意图、生成回复、决策是否评估）
  ↓
if need_evaluate?
  ↙         ↘
 true       false
  ↓           ↓
Evaluate   FinalOutput
  ↓
评估通过?
  ↙         ↘
 否         是
  ↓           ↓
retry_times < 3?  FinalOutput
  ↙         ↘
 否         是
  ↓           ↓
PlanExecute  FinalOutput
  ↓
End
```

### 4.2 条件边设计

#### route_after_plan_execute
- **源节点**：PlanExecute
- **判断条件**：`need_evaluate`
- **路由规则**：
  - `need_evaluate == true` → `evaluate`
  - `need_evaluate == false` → `final_output`

#### route_after_evaluate
- **源节点**：Evaluate
- **判断条件**：`need_evaluate` && `retry_times`
- **路由规则**：
  - `need_evaluate == false` → `final_output`（评估通过）
  - `need_evaluate == true && retry_times >= 3` → `final_output`（重试超限）
  - `need_evaluate == true && retry_times < 3` → `plan_execute`（需要重试）

## 5. 智能体分工

### 5.1 MemoryManager（记忆管理智能体）
- **职责**：检索和更新长期记忆
- **工具**：记忆检索工具、记忆更新工具
- **使用场景**：MemoryRetrieve节点、FinalOutput节点（异步更新）

### 5.2 PlanExecuteAgent（规划执行智能体）
- **职责**：理解用户意图、生成回复文本、决策是否需要评估
- **工具**：对话工具、规划工具
- **使用场景**：PlanExecute节点

### 5.3 Evaluator（评估模型）
- **职责**：评估回复质量和一致性
- **类型**：LLM（轻量级模型）
- **使用场景**：Evaluate节点

### 5.4 Summarizer（总结模型）
- **职责**：调整文本风格、生成情绪参数、处理错误响应
- **类型**：LLM
- **使用场景**：FinalOutput节点

## 6. 动态加载机制

### 6.1 节点自动发现
- **扫描目录**：`agent/graph/node/`
- **命名规则**：函数名以`_node`结尾或直接使用文件名
- **签名要求**：`def function_name(state: GlobalState) -> Dict[str, Any]`

### 6.2 条件边自动发现
- **扫描目录**：`agent/graph/edge/`
- **命名规则**：`route_after_{source_node}`
- **签名要求**：`def function_name(state: GlobalState) -> str`

### 6.3 扩展原则
- **主链路不变**：MemoryRetrieve → PlanExecute → Evaluate → FinalOutput
- **新增节点**：在对应目录下创建新文件，遵循命名和签名规范
- **新增条件边**：在edge目录下创建新文件，遵循命名和签名规范
- **工具扩展**：在`agent/util/find_tools.py`中添加新工具

---

## 7. 错误处理与重试机制

### 7.1 重试策略
- **最大重试次数**：3次
- **重试触发条件**：Evaluate节点判断需要重试
- **重试流程**：PlanExecute → Evaluate → (重试) → PlanExecute

### 7.2 错误响应
- **正常情况**：使用`summarizer_system_prompt_normal`模板
- **重试超限**：使用`summarizer_system_prompt_error`模板，生成错误异常回答

### 7.3 异步操作
- **记忆更新**：在FinalOutput节点中异步执行，不阻塞主流程
- **实现方式**：使用Python threading模块，后台线程更新记忆库



## 8. 扩展性与优化方向

### 8.1 技能扩展
- **预留字段**：`skill_names`, `skill_result`
- **扩展方式**：在PlanExecute节点中集成技能调用逻辑
- **工具集成**：通过`tools_for_plan_executor`动态加载工具

### 8.2 性能优化
- **模型选择**：根据节点复杂度选择不同规模的LLM
- **缓存机制**：记忆检索结果缓存
- **并行处理**：记忆更新等异步操作

### 8.3 功能增强
- **多轮对话**：通过messages字段维护上下文
- **个性化**：基于记忆库实现个性化回复
- **多模态**：支持图像、语音等多模态输入
