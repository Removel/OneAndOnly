## 核心技能点

### 1. FastAPI 异步编程最佳实践

#### 问题背景
在处理耗时的chat请求时，健康检查请求被阻塞，导致前端误认为后端未连接。

#### 技术原理
- **FastAPI 使用单线程异步事件循环**：所有请求共享同一个事件循环
- **同步操作会阻塞整个事件循环**：影响所有请求的处理
- **Spring Boot 使用多线程模型**：每个请求在独立线程中处理，天然支持并发

#### 解决方案
使用 `asyncio.to_thread()` 将同步操作放到线程池：

```python
import asyncio

# 错误方式：阻塞事件循环
@router.post("/chat")
async def chat(request: ChatRequest):
    result = service.chat(request)  # 阻塞操作
    return result

# 正确方式：不阻塞事件循环
@router.post("/chat")
async def chat(request: ChatRequest):
    result = await asyncio.to_thread(service.chat, request)
    return result
```

#### 关键要点
- 所有耗时的同步操作都应该使用 `asyncio.to_thread()`
- 数据库操作、文件 I/O、网络请求等都应该异步处理
- 健康检查接口应该保持轻量级，快速响应
- 理解框架的底层架构对于避免这类问题很重要

### 2. Python 数据库连接管理

#### 问题背景
数据库连接池耗尽，导致请求失败。错误信息：`QueuePool limit of size 5 overflow 10 reached`

#### 根本原因
- **连接泄漏**：连接创建后从不关闭
- **实例变量持有连接**：导致连接无法被垃圾回收
- **异常处理中创建更多连接**：加剧连接泄漏问题

#### 错误代码示例
```python
class SessionRepository:
    def __init__(self):
        self.db = None  # ❌ 实例变量长期持有连接
    
    def _get_db(self):
        if self.db is None:
            self.db = SessionLocal()  # ❌ 创建连接但从不关闭
        return self.db
    
    def create(self):
        try:
            db = self._get_db()
            # 操作...
        except Exception as e:
            db = self._get_db()  # ❌ 异常时又创建新连接
            db.rollback()
```

#### 正确代码示例
```python
class SessionRepository:
    def __init__(self):
        pass  # ✅ 不持有连接
    
    def _get_db(self):
        return SessionLocal()  # ✅ 每次创建新连接
    
    def create(self):
        db = self._get_db()
        try:
            # 操作...
            return result
        except Exception as e:
            db.rollback()
            raise
        finally:
            db.close()  # ✅ 确保连接关闭
```

#### 关键要点
- Python 需要手动管理数据库连接，不如 Spring Boot 的自动化管理
- 必须使用 `try-finally` 确保资源正确释放
- 避免在实例变量中持有数据库连接
- 每次操作都应该创建新连接，使用完毕后立即关闭

### 3. SQLite 连接池配置

#### 问题背景
SQLite 默认使用 `QueuePool`，大小为 5，溢出为 10，很容易耗尽。

#### 解决方案
为 SQLite 使用 `NullPool`：

```python
from sqlalchemy.pool import NullPool

engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False},
    poolclass=NullPool,  # ✅ SQLite 不需要连接池
    echo=False
)
```

#### 关键要点
- SQLite 是文件数据库，不需要连接池
- 使用 `NullPool` 可以避免连接池耗尽问题
- 对于 SQLite，每次操作都创建新连接是合理的

### 4. FastAPI 与 Spring Boot 架构对比

#### 线程模型对比

| 特性 | Spring Boot | FastAPI |
|------|-------------|---------|
| **线程模型** | 多线程（线程池） | 单线程异步事件循环 |
| **请求处理** | 每个请求独立线程 | 所有请求共享事件循环 |
| **阻塞影响** | 只影响当前线程 | 影响所有请求 |
| **数据库管理** | Spring 自动管理 | 需要手动管理 |
| **连接池** | HikariCP 自动管理 | SQLAlchemy 需要配置 |

#### 优势对比

**Spring Boot 优势：**
- ✅ 多线程模型，天然支持并发
- ✅ 阻塞操作不影响其他请求
- ✅ 成熟的线程池管理
- ✅ 开发者无需关心异步编程
- ✅ 自动事务管理和资源管理

**FastAPI 优势：**
- ✅ 更高的性能（异步 I/O）
- ✅ 更低的内存占用
- ✅ 更适合 I/O 密集型应用
- ✅ 现代化的异步编程模型
- ✅ 更好的并发处理能力

#### 迁移注意事项
1. **资源管理**：从自动管理转为手动管理
2. **异步编程**：需要理解异步编程的最佳实践
3. **阻塞操作**：必须避免阻塞事件循环
4. **连接管理**：需要手动管理数据库连接
5. **错误处理**：需要更细致的错误处理和资源清理

## 最佳实践总结

### 1. 异步编程规范
- 所有耗时的同步操作都应该使用 `asyncio.to_thread()`
- 数据库操作、文件 I/O、网络请求等都应该异步处理
- 健康检查接口应该保持轻量级，快速响应
- 使用性能监控工具检测事件循环阻塞情况

### 2. 数据库连接管理规范
- 每次操作都创建新连接
- 使用 `try-finally` 确保连接正确关闭
- 避免在实例变量中持有数据库连接
- 对于 SQLite，使用 `NullPool` 避免连接池问题

### 3. 错误处理规范
- 在 `finally` 块中确保资源释放
- 避免在异常处理中创建新的资源
- 记录详细的错误日志，包括堆栈跟踪
- 提供有意义的错误信息

### 4. 性能优化规范
- 使用异步处理提升并发能力
- 监控系统性能指标
- 定期进行性能测试
- 优化数据库查询和索引
